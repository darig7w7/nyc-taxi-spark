¿Por qué Docker?
En producción Spark corre en cientos de servidores físicos. Docker simula ese cluster en una sola máquina con contenedores aislados — sin instalar Java, Spark ni configurar variables de entorno manualmente.

SPARK DRIVER vs WORKER
Driver — el cerebro
Ejecuta analytics.py, construye el DAG de operaciones, divide los datos en particiones y asigna Tasks a los Workers. Tiene visibilidad global del job. Corre en nyc-spark-job.
Worker — el ejecutor
Recibe su partición de datos, aplica filtros y transformaciones en RAM, calcula métricas y devuelve el resultado al Driver. Solo conoce su fracción del dataset.

Job PySpark — SparkSession, Lectura y Limpieza
1 · SparkSession — punto de entrada
spark = SparkSession.builder \
  .appName("NYC_Taxi_Analytics") \
  .config("spark.driver.memory", "4g") \
  .getOrCreate()
2 · Leer Parquet — Spark divide en particiones
for anio in [2019, 2020, ..., 2026]:
  path = f"data/yellow_tripdata_{anio}-04.parquet"
  df = spark.read.parquet(path)
  df = df.withColumn("anio", lit(anio))
3 · Limpieza — filtrar inválidos
df_clean = df \
  .filter(col("trip_distance") > 0) \
  .filter(col("fare_amount") > 0) \
  .filter(col("passenger_count") > 0)
SparkSession
Punto de entrada al cluster. Sin SparkSession no hay conexión con el motor distribuido. Es el puente entre el código Python y Spark.
Particiones
Al leer el Parquet el Driver divide el archivo en particiones. Cada partición va a un Executor para procesarse en paralelo. Por defecto 2 × número de cores.
Transformaciones Lazy
filter() no ejecuta nada — solo agrega al DAG. Spark acumula todas las transformaciones y las optimiza antes de ejecutar en la acción final.
Registros eliminados
De 28,058,885 registros totales — 3,200,755 eran inválidos (11.4%). Datos reales siempre tienen errores: GPS fallido, tarifas negativas, viajes cancelados.

df_join = df_clean.join(zones,

  how="left")
# PULocationID=161 -> "Midtown" -> "Manhattan"
Agrupar + guardar particionado
resultado = df.groupBy("anio").agg(
  count("*").alias("total_viajes"),
  avg("fare_amount").alias("tarifa_prom"))

resultado.write \
  .partitionBy("anio") \
  .parquet("output/comparativa_anual")
Shuffle — la operación más costosa
El JOIN y el groupBy requieren mover datos entre Workers por la red para que registros con el mismo key queden en el mismo Executor. Es la operación más lenta — por eso minimizamos los JOINs.

Fase Map: cada Worker agrega su partición. Fase Shuffle: datos del mismo año al mismo Executor. Fase Reduce: resultado final por año.

DuckDB · Superset
Spark vs Hadoop
DuckDB — puente SQL
Lee los Parquet de output/ directamente sin importar. Crea tablas SQL que Superset puede consultar. Zero configuración — embebido en Python. Alternativa a PostgreSQL para analítica local.
Superset — Dashboard
Plataforma BI open source creada por Airbnb en 2015. Usada por Netflix, Lyft y Dropbox. Alternativa gratuita a Tableau y Power BI. 40+ tipos de gráficos sin código.
