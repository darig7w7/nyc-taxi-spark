Análisis de Tradeoffs
del Stack Tecnológico

Justificación de arquitectura: Procesamiento, Almacenamiento, Visualización y Orquestación

Procesamiento: Escala vs. Latencia

  • Apache Spark & PySpark (3.5.5)
    El motor distribuido permite procesar Petabytes de datos y PySpark acelera el desarrollo para data scientists.
    Tradeoff: Alto overhead de inicialización. Es excesivo y lento para datasets pequeños debido a la coordinación del cluster.
  • DuckDB (1.1.3)
    Motor SQL in-process. Brilla ejecutando analítica columnar ultrarrápida (Zero-copy) sobre archivos locales.
    Tradeoff: Limitado a un solo nodo. Si el dataset excede la memoria RAM/Disco local, el procesamiento falla.

Estrategia de Almacenamiento

Formato Parquet

Almacenamiento columnar altamente tipado. Permite escanear solo las columnas necesarias (Pruning), acelerando drásticamente las consultas OLAP.

Tradeoff: Complejo de generar comparado con CSV o JSON.

Compresión Snappy

Algoritmo de compresión por defecto. Minimiza el espacio en disco sin consumir excesivos ciclos de CPU durante la descompresión al vuelo.

Tradeoff: Menor ratio de compresión que GZIP/ZSTD.

Inmutabilidad

Ideal para Data Lakes. Los archivos estáticos garantizan consistencia y facilitan la distribución en sistemas HDFS o S3.

Tradeoff: Pésimo para actualizaciones (Updates). Requiere reescribir particiones enteras.

Presentación e Infraestructura

Apache Superset

Plataforma de BI moderna y open-source. Permite exploración visual intuitiva y creación de dashboards interactivos con soporte nativo para múltiples motores (incluyendo Spark y DuckDB).

Tradeoff: Complejidad Operativa
Para funcionar correctamente en producción, exige desplegar y mantener infraestructuras adicionales (PostgreSQL para metadata, Redis para caché y Celery workers).

Docker Compose (2.x)

Herramienta de orquestación local. Define y ejecuta aplicaciones multi-contenedor. Garantiza que el entorno de desarrollo sea idéntico para todo el equipo en un solo comando.

Tradeoff: Límites de Producción
No está diseñado para escalado horizontal automático, recuperación de fallos (self-healing) ni zero-downtime deployments. No reemplaza a Kubernetes.
